## 用户可见行为

- `BATCH_ENABLED` 关闭：隐藏 Batch 入口，直接访问页面显示不可用。
- `BATCH_MIN_ROLE` 决定提交新批次和修改 webhook 的角色门槛，默认 `internal`。
- 低于门槛但仍有自己的批次或 webhook：保留入口与历史管理能力；没有历史则隐藏。
- API key 的存在、轮换及额度不影响历史管理；数据接口继续检查所有者。
- 仪表盘区分用户工具和管理工具。Admin Console 沿用已有两项配置。
- UI 创建任务流程属于后续阶段。

## 运行验证

使用独立测试数据库、真实本地 FastAPI/Next.js 服务、合成账号和模拟推理服务；
没有调用真实付费模型或修改生产配置。

Codex 独立确认：

- internal/admin 可以看到入口；无历史的 free 用户在默认门槛下没有入口。
- 真实批次完成后，将所有者降为 free 并删除执行 key，仍可查看及下载结果。
- 其他账号下载该结果返回 404；匿名能力查询返回 401。
- 浏览器切换到无历史账号后不残留旧账号任务。
- Admin API 将门槛调整为 free 后，浏览器显示该账号的 Batch 入口。
- 关闭总开关后所有角色的能力响应均隐藏入口，用户数据接口返回 404，管理员
  Batch 总览仍返回 200；浏览器直接访问显示“批量推理不可用”。

角色变更沿用已有用户缓存：Admin API 修改角色会清缓存，直接 SQL 修改可能等待
原有 60 秒缓存过期。此记录不构成生产发布验收。
