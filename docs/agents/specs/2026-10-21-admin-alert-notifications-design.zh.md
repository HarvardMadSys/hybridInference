# 管理台单渠道告警通知配置

日期：2026-10-21

状态：设计已确认；扩展 2026-10-20 Webhook 通知适配方案的管理台交互。

## 范围与界面

`Admin → Configuration → Alerts` 提供一个 `Notification channel` 下拉框，
选项为 `None`、`Slack`、`WeCom`。选择 Slack 时只展示 Slack Webhook 编辑器；
选择 WeCom 时只展示企微编辑器；None 不展示凭证输入。未实现的渠道不出现在下拉框中。

凭证沿用只写交互：已配置只显示 Set，可替换或清空，不向浏览器返回保存的 URL。
管理台暂停和分类静默的文案使用通用的告警通知措辞。

## 配置兼容与保存

不新增另一套配置存储或渠道开关。下拉框从已有 URL 的配置状态推断当前选择，
旧部署的 `SLACK_ALERTS_WEBHOOK_URL` 及其 `SLACK_WEBHOOK_URL` 回退继续有效。
已有专用 Slack 配置继续编辑该键；首次配置 Slack 使用 `SLACK_WEBHOOK_URL`，
保持现有失败请求检测器的启用条件。保存与测试均使用去除首尾空白后的 URL。
选择其他渠道时，未保存的凭证草稿被丢弃；取消修改恢复服务器返回的配置。

一次保存原子地完成渠道切换：

- Slack → WeCom：写入企微 URL，并把两个 Slack 配置保存为空字符串。
- WeCom → Slack：写入所选 Slack 配置，并把企微配置保存为空字符串。
- None：把三个 Webhook 配置都保存为空字符串。
- 目标渠道没有地址时阻止保存，避免误清空原来的可用渠道。

保存空字符串会覆盖环境变量；删除数据库配置行会恢复环境变量，不能用于渠道切换。
因此被关掉的渠道需要在告警卡片上保留 Reset 入口：它删除该行（后端 `DELETE
/admin/config/{key}`），让设置重新跟随环境变量。否则一次 None 保存就会把 `.env`
里的 webhook 永久压住，界面上再无恢复途径。已保存但未选中的渠道、以及当前渠道的
已保存值，都在卡片内提供 Reset；Reset 后重新推导渠道，并清除待保存的渠道选择。
Webhook 设置统一需要重启。保存后提示 Pending restart，正式告警在重启前继续走旧渠道，
重启后新渠道整体生效。现有去重、冷却、静默、检测器注册和恢复补发流程不变。

## 测试通知

管理员点击 `Send test notification` 后，浏览器请求 `POST /admin/alerts/test`：

```json
{"channel": "wecom", "webhook_url": "<unsaved draft, optional>"}
```

显式提供 URL 时测试当前草稿；省略时由后端读取该渠道最新保存的凭证，包含尚待重启的值。
读取前刷新数据库配置，避免多进程中保存后立刻测试使用旧凭证；刷新失败则拒绝测试。
响应包含渠道、成功标记和测试编号，不包含凭证。成功表示平台 API 接受发送，管理员仍可通过
编号在接收群确认实际送达。失败返回不含地址和令牌的错误。

临时填写的地址只允许已实现渠道的官方 HTTPS Webhook 地址，避免管理员会话被用来
驱动服务端请求任意地址；已保存的地址本身已被信任（正式告警本来就会向它发送），
因此只要求是 HTTPS，Slack 兼容服务（Mattermost、Rocket.Chat、出口代理等）也能测试。
测试请求由管理员鉴权、按管理员发送节流和凭证脱敏保护。测试不保存配置，也不占用正式告警的去重、冷却或恢复状态，直接调用
同一渠道的渲染和发送适配器。消息明确标记为测试，附带唯一编号。

测试进行中阻止重复提交和切换表单；修改配置后清除过期的测试结果。保存新渠道但未重启时，
测试可以验证新配置，正式通知仍然使用原渠道。界面应明确这一区别。

## 验证与后续渠道

自动验证覆盖：旧 Slack 配置推断、隐藏其他渠道字段、双向切换的一次保存、取消草稿、
空目标拒绝、None、秘密不回显、测试草稿与已保存配置、pending restart 取值、
管理员鉴权、非法 URL、发送失败以及正式告警状态不受测试影响。

浏览器验收应实际选择两个渠道、修改后取消、保存并检查重启提示；企微测试通过唯一编号确认。
自动化测试在隔离测试环境运行，线上通知验收与自动化结果分别记录。

Discord、Telegram 和自定义 Webhook 为后续扩展，复用 `AlertSink` 接口。
每个新增渠道需要自己的配置字段、消息格式和响应判定；通用 Webhook 需要约定接收 JSON，
不能宣称任意平台 URL 都可以直接使用。独立的 status-monitor 告警控制平面不在本次范围内。
