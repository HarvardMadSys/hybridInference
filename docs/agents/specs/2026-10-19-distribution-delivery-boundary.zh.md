# 发行版邮件与短信发送边界

日期：2026-10-19。范围：修复腾讯发送配置进入 FreeInference 管理后台的问题。

## 所有权

HybridInference 保留账户流程、邮件事件、手机号规范化、验证码存储与限额，以及通用发送和配置注册接口。发行版通过显式加载的后端扩展注册所需发送实现、配置项与校验条件。未加载扩展的发行版不提供该发送选项，也不接受或列出其专属配置。

腾讯云 SES、SMS 和 TC3 签名是厂商集成，不是发行版：国内推理平台普遍需要，因此作为可选模块 `serving.integrations.tencent_cloud` 留在核心，与参考邮件模板和测试放在一起。核心默认不加载它；部署把它加入 `BACKEND_EXTENSIONS` 才提供 `tencent_ses`、`tencent` 两个选项和对应配置。每个发行版也可以用同一组接口注册自己的发送实现。现有 `BACKEND_EXTENSIONS` 加载顺序在数据库配置初始化之前，继续作为可信部署模块的入口。核心不根据发行版名称决定行为，不导入任何发行版实现。

属于具体部署的内容留在发行版：审核通过的模板 ID 与模板内容、发件身份、默认短信服务和 +86 号码策略，以及与发送无关的模型凭据。

## 配置和兼容

扩展保留旧配置名称，使用统一 `config_value()` 读取数据库、环境变量和注册默认值。数据库值优先，秘密值保持遮蔽，运行时刷新继续生效。扩展只能添加自己的配置项，不能覆盖核心条目；重复发送注册或无效配置使初始化失败。

旧版本把腾讯配置存入了通用表，没有记录所有者。核心不保留任何历史名称清单，也不为配置行增加所有权模型：加载腾讯云模块时，这些行重新成为它的配置条目；未加载时，按核心对所有未注册行的既有规则列为普通自定义配置，秘密标记保留，没有代码读取，管理员可以删除。FreeInference 等从未使用腾讯发送的部署没有这类行。数据库结构不变，升级和回滚都不需要迁移配置表。

SMTP 是核心默认邮件实现，短信默认关闭。选择未安装的服务不得静默回退；邮件事件及模板变量契约、短信验证码语义保持不变。

## 腾讯迁移顺序

SSV 固定配套的核心提交，扩展变更与核心版本在同一个发行版提交中切换。SSV 删除自己的腾讯云发送副本，改为在 `BACKEND_EXTENSIONS` 中加载 `serving.integrations.tencent_cloud`；原有凭据和模板 ID 不改名；腾讯发行版继续提供默认短信服务和 +86 号码策略，显式环境和数据库值优先。扩展内容必须参与后端镜像来源校验及构建复用摘要，避免复用不含扩展或包含旧扩展的镜像。

GitHub 变更通过审查后，工蜂同步保留上游导入历史与腾讯功能差异。生产晋升独立于源码同步和 staging 验收。

## 验证

- 未加载腾讯云模块时，核心及 FreeInference 配置 API 不出现腾讯字段或发送选项；加载后通过真实扩展加载路径提供两项服务和全部配置；残留的旧行只作为普通自定义配置出现，秘密值保持遮蔽。
- 模型 YAML 引用的变量、编号 provider key 和管理员自定义配置在升级后照常生效。
- 已安装扩展的配置验证、缺失项提示、秘密遮蔽、默认值、数据库优先级及刷新保持一致。
- 腾讯签名、临时凭据、短信目的地、验证码、SES 事件模板、固定链接与异常返回保持原契约。
- SSV 打包、来源摘要和后端复用检查覆盖扩展内容；发行版包只与其固定的核心提交组合使用。
- 自动测试在腾讯 DevCloud 隔离目录与一次性数据库执行。模拟发送只证明调用与响应处理，不声称证明真实短信或邮件送达。
